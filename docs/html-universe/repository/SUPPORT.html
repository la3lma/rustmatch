Support

Rustmatch is in design and early development. There is no stable release, production support promise, or response-time guarantee yet.

Where to ask

  • Use the issue tracker for reproducible bugs, concrete feature proposals, documentation problems, and measured performance regressions.
  • Use the repository's issue forms when available; they ask for the evidence needed to investigate efficiently.
  • Read the README, roadmap, and contribution guide before opening an issue.

Search existing issues first. A small reproducer, exact revision, Rust version, platform, expected result, and actual result are much more useful than a broad symptom report.

Other channels

  • Report suspected vulnerabilities privately as described in SECURITY.md.
  • Report conduct concerns privately as described in CODE_OF_CONDUCT.md.
  • Architecture and semantic proposals should name the relevant roadmap or use-case ID and explain their compatibility and evidence implications.

The maintainers may convert support requests into documentation or issue tracker improvements so that the answer remains available to others.
